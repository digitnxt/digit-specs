# Business Rules — Filestore Service

## Cross-Field Rules

### BR-CF-001: File extension must match allowed formats

**Entities involved:** Artifact, DocumentCategory (`allowedFormats`)  
**Rule:** When uploading a file, the file's extension must exist in the `allowedFormats` array of the DocumentCategory whose `type` matches the `module` parameter. Comparison is case-insensitive.  
**Violation response:** 400 — `INVALID_REQUEST`

---

### BR-CF-002: File size must be within category bounds

**Entities involved:** Artifact, DocumentCategory (`minSize`, `maxSize`)  
**Rule:** If `minSize` or `maxSize` is defined on the matching DocumentCategory, the uploaded file's size must be within those bounds. Size values use the pattern `^\d+(\.\d+)?(KB|MB|GB)$`; conversion: `1KB = 1024 bytes`, `1MB = 1024×1024 bytes`, `1GB = 1024×1024×1024 bytes`.  
**Violation response:** 400 — `INVALID_REQUEST`

---

### BR-CF-003: Multipart form total capped at 32 MB

**Entities involved:** StorageHandler, upload request  
**Rule:** The total multipart form body is limited to 32 MB. Requests exceeding this are rejected before any file content is processed.  
**Violation response:** 400 — `INVALID_REQUEST`

---

### BR-CF-004: DocumentCategory type uniqueness per tenant

**Entities involved:** DocumentCategory (`type`, `tenantid`)  
**Rule:** Within a single tenant, no two DocumentCategory records may have the same `type` value. The `(tenantid, type)` combination must be unique.  
**Violation response:** 409 — `CONFLICT`

---

## Cross-Schema Rules

### BR-CS-001: Upload requires active DocumentCategory

**Entities involved:** Artifact, DocumentCategory  
**Rule:** Before any file upload (direct or presigned), the service queries for a DocumentCategory where `type = module`, `tenantid = X-Tenant-Id`, and `isactive = true`. If no matching active category exists, the upload is rejected. An artifact cannot be created without a prior active category.  
**Violation response:** 400 — `INVALID_REQUEST`

---

### BR-CS-002: Tenant isolation on all table queries

**Entities involved:** Artifact (`eg_filestoremap_v2`), DocumentCategory (`eg_doc_metadata_v2`)  
**Rule:** All queries on both tables are scoped to `tenantid = X-Tenant-Id`. A request from one tenant cannot read or write another tenant's artifacts or categories.  
**Violation response:** 404 — `NOT_FOUND` (implicit; other tenant's data not returned)

---

## Lifecycle Rules

### BR-LC-001: Presigned URL expires after 1 hour

**Entities involved:** Artifact, S3  
**Rule:** A presigned PUT URL generated by `POST /upload-url` is valid for 1 hour. If the client does not upload within this window, the artifact row is cleaned up when `POST /confirm-upload` is subsequently called and the S3 object is not found.  
**Violation response:** 200 — `{ "status": "INVALID" }` (signals failure to caller)

---

### BR-LC-002: Inactive category blocks future uploads

**Entities involved:** DocumentCategory (`isActive`)  
**Rule:** Setting `isActive = false` on a category prevents new uploads using that `module`/`type`. Existing artifacts previously uploaded under that category remain queryable and downloadable; only new uploads are blocked.  
**Violation response:** 400 — `INVALID_REQUEST` ("Document category is not active")

---

### BR-LC-003: Optimistic lock on category updates

**Entities involved:** DocumentCategory (`version`)  
**Rule:** The `version` field in `eg_doc_metadata_v2` must match the current server version on `PUT`. If another process has modified the category concurrently, the update is rejected and the client must re-fetch and retry.  
**Violation response:** 409 — `CONFLICT`

---

### BR-LC-004: CreatedBy and createdTime are immutable

**Entities involved:** DocumentCategory (`auditdetail.createdBy`, `auditdetail.createdTime`)  
**Rule:** `createdBy` and `createdTime` are set once when the category is created and are never overwritten. Only `modifiedBy` and `modifiedTime` change on updates.  
**Violation response:** N/A (enforced by service layer)

---

## Cross-Module Rules

### BR-CM-001: S3 dual-bucket strategy for read and write

**Entities involved:** Artifact, S3 (`S3_BUCKET`, `S3_READ_BUCKET`)  
**Rule:** Upload (write) operations use `S3_BUCKET`. Download and URL generation (read) operations use `S3_READ_BUCKET`. Object keys are constructed as `{module}_{tenantid}/{uuid}/{filename}`. If the write bucket is inaccessible, uploads fail.  
**Violation response:** 500 — `INTERNAL_ERROR`

---

### BR-CM-002: PubSub events are fire-and-forget

**Entities involved:** Artifact, DocumentCategory, PubSub  
**Rule:** After any successful mutation (upload, category create/update/delete), an event is published to the configured PubSub topic. Publish failures are logged but do not fail the HTTP response.  
**Violation response:** N/A (caller sees 200/201)

---

## Error Reference

| HTTP Status | Condition | Error Code |
|---|---|---|
| 400 | Missing `X-Tenant-Id` header | `INVALID_REQUEST` |
| 400 | No files provided in multipart form | `INVALID_REQUEST` |
| 400 | File format not in category's `allowedFormats` | `INVALID_REQUEST` |
| 400 | File size outside `minSize`/`maxSize` bounds | `INVALID_REQUEST` |
| 400 | `module` matches no active DocumentCategory | `INVALID_REQUEST` |
| 400 | Multipart form exceeds 32 MB | `INVALID_REQUEST` |
| 404 | File (`fileStoreId`) not found for tenant | `NOT_FOUND` |
| 404 | DocumentCategory not found | `NOT_FOUND` |
| 409 | Category `(tenantid, type)` duplicate | `CONFLICT` |
| 409 | Category version mismatch on update | `CONFLICT` |
| 500 | S3 read/write failure | `INTERNAL_ERROR` |
| 500 | Database error | `INTERNAL_ERROR` |
