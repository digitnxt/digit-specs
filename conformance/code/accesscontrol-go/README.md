# AccessControl Service

Centralized rules store for **RBAC** (role-based path/method authorization)
and **JBAC** (jurisdiction-based access control) decisions. The Kong
gateway's `rbac` and `jbac` plugins consume the internal endpoints from this
service, cache the rule set, and make per-request decisions at the edge.

Tenant scoping is by `tenant_id` column — accesscontrol is a shared-schema
service, no per-tenant Flyway migrations.

---

## Base path

| Environment | Base URL |
|---|---|
| Local (port-forwarded) | `http://localhost:8080/access/v3` |
| LTS (Kong gateway)     | `https://digit-lts.digit.org/access/v3` |
| Configurable via       | `SERVER_CONTEXT_PATH` (default `/access`) |

---

## API surface

### RBAC rules — tenant-scoped (requires `X-Tenant-ID`)

| Method | Path | Purpose |
|---|---|---|
| `GET`  | `/rbac/rules/` | List rules for the tenant. Supports `roleName`, `httpMethod`, `effect`, `enabled` filters; paginated by `limit` (0–100) / `offset` (0–10000). |
| `POST` | `/rbac/rules/` | Create one rule. Requires `X-User-ID`. |
| `POST` | `/rbac/rules/bulk` | Create up to N rules atomically (all-or-nothing). Requires `X-User-ID`. |
| `DELETE` | `/rbac/rules/tenant` | Bulk-delete every rule for the tenant. |
| `GET`  | `/rbac/rules/{id}/` | Get a single rule. |
| `PATCH` | `/rbac/rules/{id}/` | Partially update a rule. Requires `X-User-ID`. |
| `DELETE` | `/rbac/rules/{id}/` | Delete a single rule. |

### JBAC rules — tenant-scoped (same shape as RBAC)

| Method | Path | Purpose |
|---|---|---|
| `GET`  | `/jbac/rules/` | List JBAC rules. Filters: `name`, `enforcement`. |
| `POST` | `/jbac/rules/` | Create one rule. |
| `POST` | `/jbac/rules/bulk` | Bulk create. |
| `DELETE` | `/jbac/rules/tenant` | Bulk delete by tenant. |
| `GET`  | `/jbac/rules/{id}/` | Get a single rule. |
| `PATCH` | `/jbac/rules/{id}/` | Partial update. |
| `DELETE` | `/jbac/rules/{id}/` | Delete. |

### Internal — Kong plugin endpoints (NO tenant header)

| Method | Path | Consumer |
|---|---|---|
| `GET`  | `/internal/rbac/rules` | Kong `rbac` plugin — fetches the global rule set, paginated by `limit` / `offset` (0–1000 / 0–100000). |
| `GET`  | `/internal/rbac/rules/version` | Kong `rbac` plugin — cheap cache-invalidation check. Returns `{"version": "<hash>"}`. |
| `GET`  | `/internal/jbac/rules` | Kong `jbac` plugin. |
| `GET`  | `/internal/jbac/rules/version` | Kong `jbac` plugin. |

These routes are **not** intended for direct client traffic — they exist
because the gateway needs to bypass tenant scoping to fetch everything.

### Operational

| Method | Path | Purpose |
|---|---|---|
| `GET`  | `/health` | Liveness probe. |

## Headers contract

| Header | Required | Notes |
|---|---|---|
| `X-Tenant-ID` | Required on tenant-scoped routes | Sets the row-level scope. Internal routes ignore this. |
| `X-User-ID` | Required on writes (POST, PATCH) | Audit-author for `createdBy` / `modifiedBy`. Middleware-enforced. |
| `X-Request-ID` | Optional | Generated by the service if absent. Returned on every response. |
| `Authorization: Bearer <token>` | Validated by Kong | The service trusts the gateway. |

## Error envelope

Every error response is a JSON array:

```json
[
  {
    "code":        "AccessControl.NotFound",
    "message":     "No RBAC rule found with the specified ID for this tenant"
  }
]
```

Common codes:

| Code | Status |
|---|---|
| `AccessControl.InvalidRequest` | 400 |
| `AccessControl.ValidationFailed` | 400 (one entry per failing field) |
| `AccessControl.NotFound` | 404 |
| `AccessControl.InternalError` | 500 |

## Rule shapes

### RBAC rule

```json
{
  "id":          "f0e7e2c8-...",
  "tenantId":    "pg",
  "roleNames":   ["EMPLOYEE_ADMIN", "HR_USER"],
  "httpMethod":  "POST",
  "path":        "/employee/v3/employees",
  "effect":      "ALLOW",
  "priority":    100,
  "enabled":     true,
  "constraints": null,
  "description": "HR admins can create employees",
  "auditDetails": { "createdBy": "...", "createdTime": 0, "modifiedBy": "...", "modifiedTime": 0 }
}
```

- `path` supports `*` (trailing wildcard) and parameterised segments
  `{param:UUID}` / `{param:ALNUM}`.
- `effect` is `ALLOW` or `DENY`. `DENY` wins on the same priority.
- `priority` defaults to `0`; higher = evaluated first.

### JBAC rule

```json
{
  "id":            "c1f8...-...",
  "tenantId":      "pg",
  "name":          "Employee jurisdiction guard",
  "pathPattern":   "/employee/v3/employees",
  "methods":       ["POST", "PUT", "PATCH"],
  "enforcement":   "REQUIRED",
  "parentImpliesChildren": true,
  "extractJurisdiction": {
    "required": true,
    "sources": [
      { "from": "body", "path": "$.jurisdictions[*].boundaryRelation[*].code" }
    ]
  },
  "description":   "All employee writes must be within caller's jurisdictions"
}
```

- `enforcement` is `REQUIRED`, `OPTIONAL`, or `DISABLED`.
- `parentImpliesChildren` lets a user with a parent boundary access child
  boundaries when the boundary service's hierarchy is consulted.

## Example: create RBAC rule

```bash
curl -sS -X POST 'https://digit-lts.digit.org/access/v3/rbac/rules/' \
  -H 'Content-Type: application/json' \
  -H 'X-Tenant-ID: pg' \
  -H 'X-User-ID: 00000000-0000-0000-0000-000000000001' \
  -H 'Authorization: Bearer '"$ACCESS_TOKEN" \
  -d '{
    "roleNames":  ["EMPLOYEE_ADMIN"],
    "httpMethod": "POST",
    "path":       "/employee/v3/employees",
    "effect":     "ALLOW",
    "priority":   100,
    "enabled":    true,
    "description":"HR admins can create employees"
  }'
```

## Example: bulk create

```bash
curl -sS -X POST 'https://digit-lts.digit.org/access/v3/rbac/rules/bulk' \
  -H 'Content-Type: application/json' \
  -H 'X-Tenant-ID: pg' \
  -H 'X-User-ID: 00000000-0000-0000-0000-000000000001' \
  -H 'Authorization: Bearer '"$ACCESS_TOKEN" \
  -d '{
    "rules": [
      { "roleNames": ["HR_USER"],       "httpMethod": "GET",  "path": "/employee/v3/employees/*", "effect": "ALLOW" },
      { "roleNames": ["EMPLOYEE_ADMIN"], "httpMethod": "PUT",  "path": "/employee/v3/employees/{param:UUID}", "effect": "ALLOW" }
    ]
  }'
```

## Example: Kong plugin fetch

```bash
# Internal — used by the rbac Kong plugin every reload_interval seconds.
curl -sS 'http://localhost:8080/access/v3/internal/rbac/rules?limit=1000&offset=0'
curl -sS 'http://localhost:8080/access/v3/internal/rbac/rules/version'
```

## Local development

```bash
# Apply migrations (one-off, public schema)
./db/migrate.sh up

# Run the service
go run ./cmd/server
```

The Kong gateway needs to be able to reach `http://accesscontrol:8080`
(or whatever the in-cluster name is) for its `rbac` and `jbac` plugins to
fetch the rule set.
